Data flow

What happens when a user changes a filter on the Dashboard.

  1. User sets a filterTime period, warehouse, category or order status in FilterBar.vue. State lives in useFilters(), a module-level singleton shared by every view.
  2. View builds the requestThe view calls getCurrentFilters() and passes the result to api.js, which drops any value equal to all and builds the query string.
  3. FastAPI filters in memoryThe route runs apply_filters() and filter_by_month() over the lists loaded from JSON. Quarters such as Q3-2025 expand to three months.
  4. Pydantic validates the responseTyped routes return a response_model; the dashboard summary computes totals (inventory value, low-stock count, pending orders) on the fly.
  5. Raw data lands in refsViews store results in refs such as allOrders and inventoryItems.
  6. Computed properties derive the UICharts, status breakdowns, top products and revenue-goal progress are computed from the refs, so the screen updates without extra requests.

Things to know

  • The client calls /api/tasks and /api/purchase-orders (create, toggle, delete), but main.py defines no POST, PATCH or DELETE routes. Those calls will fail until the backend implements them.
  • views/Backlog.vue exists but has no route in main.js; backlog data is shown on the Dashboard instead.
  • api.js hardcodes http://localhost:8001/api, so the frontend is not configurable per environment.
  • Inventory has no time dimension, so the month filter applies to orders only.
  • Because data is loaded at import time and never written back, any mutation is lost on restart.
